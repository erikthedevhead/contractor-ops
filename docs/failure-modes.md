# Failure modes

Two sources: problems found while building against the real QuickBooks
sandbox and real models (below), and the eval suite's measured failures
(`docs/eval-report.md`, regenerated by `pnpm eval`). Each entry: what
happened, why it mattered, the fix, and the test that now guards it.

## Found during the build

| # | Failure | How it surfaced | Why it matters | Fix | Guarded by |
|---|---|---|---|---|---|
| 1 | QuickBooks sent the **legacy webhook format** although the docs say it was retired | First live webhook was rejected by the CloudEvents-only parser | Every change would have been dropped | Parse both formats; derive a deterministic id for legacy events | `webhooks.unit.test.ts` (real sandbox payload), `webhook-flow.db.test.ts` |
| 2 | **Payments don't notify about the invoices they change** | Live test: payment synced, invoice balance stale | "Who owes me money" would be wrong until the nightly reconcile | Refresh every invoice a payment applies to, before and after | `webhook-flow.db.test.ts` (legacy payment case) |
| 3 | **Raw-first storage recovered a rejected delivery** | Delivery #1 replayed after the parser fix | Without it the first payment would have been lost | `webhooks:reingest` replays stored, signature-verified deliveries | `webhook-flow.db.test.ts` (replay) |
| 4 | **Job claim locked more rows than requested** | Out-of-order webhook test left a job stuck in `running` | Jobs silently orphaned until the reaper ran | `MATERIALIZED` CTE around `FOR UPDATE SKIP LOCKED ... LIMIT n` | `queue.db.test.ts` (claim locks exactly n) |
| 5 | **Unknown customer id returned "owes $0.00"** | Operator typo during a live MCP check | A confident wrong answer an agent would repeat | Tools taking `customer_id` verify it and return `NOT_FOUND` with a hint | `mcp.db.test.ts` |
| 6 | **Silent truncation** of job history at the default limit | Agent said "I found 10 bathroom remodels" (there were 16) | Conclusions drawn from a partial list presented as complete | `total_matches` + `truncated` + a note; prompt rule | `mcp.db.test.ts` (truncation signal) |
| 7 | **Oversized tool results cut mid-JSON** | Estimator test with 20 comparable jobs | Model handed invalid JSON | Oversized results wrapped as valid JSON marked `result_truncated`; descriptions shortened | `agent.unit.test.ts`, `estimator.db.test.ts` |
| 8 | **Internal ids shown to users** ("estimate #249" vs doc #1041) | Live estimate conversation | The contractor can't find "#249" in QuickBooks | Prompt rule: refer to documents by `doc_number` | eval cases (reply text) |
| 9 | **Environment mix-up**: local agent pointed at production MCP | Shell `export MCP_URL` overrode `.env` | Confusing 401s; risk of acting on the wrong tenant | Startup probes log the MCP/Estimator URLs they reached and warn on mismatch | startup logs |
| 10 | **Secret fragment echoed** by env validation | Misformatted `TOKEN_ENC_KEYS` in production `.env` | Partial key in log files | Validator never quotes values | `env.unit.test.ts` |
| 11 | **Config error crash-looped** (164 restarts, 50% CPU) on a shared box | Same incident | Starved the co-hosted app | PM2 `min_uptime` / `max_restarts` | ecosystem config |

## Measured by the eval suite

See `docs/eval-report.md`. Failure modes are categorized as:
`wrong_or_missing_number`, `missing_entity`, `extra_entity`,
`hallucinated_answer`, `missed_ambiguity`, `no_refusal`, `unsafe_write`,
`missing_write`, `duplicate_write`, `estimate_out_of_tolerance`,
`estimate_missing_item`, `no_estimate_produced`, `recovery_failed`,
`agent_error`.
